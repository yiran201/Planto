# AGENTS.md

规则分三层，冲突时严格按优先级仲裁：P0 强制，绝不可违反；P1 默认遵循，
可记录理由后偏离；P2 仅供参考。

## P0｜强制层（精确触发，违反需人工整体回退，不是补记录就算了）

P0-1 模块边界：只改当前任务指定的模块。一旦越界，视为严重违规，需要
人工整体回退该任务改动，不能"下个任务里补救"。

P0-2 信息不足就停（触发条件精确化，不满足以下任一条件不允许停下来问）：
- 验收标准没有可判断"做对了没"的具体标准
- 改动属于破坏性变更（删除/重命名现有字段、改变现有方法的行为或签名），
  导致现有调用方观察到不同结果——增量变更（新增字段/新增方法/新增可选
  参数）不算，不需要为此停下来
- 与 KNOWLEDGE.md 中来源标注为"用户提供"或"现有代码梳理"的项目专属
  规则冲突
不满足以上条件时，必须自己决定并继续推进，不允许以"看起来不清晰"为由
反复确认。

P0-3 项目专属决策必须有明确来源：技术选型、架构、数据结构，以及计价/
权限/状态机等项目专属业务规则，不能只靠网络调研得出，必须来自用户或
现有代码。网络调研得到的"行业惯例/通用做法"可写入 KNOWLEDGE.md 作参考，
但不能替代项目专属决策的来源。一旦发现某条规则只有网络调研来源、且属于
项目专属决策，必须停下来问；若未停下直接采用，事后发现视为严重违规，
需要整体回退该任务改动。

## P1｜默认层（边界内最大自主权）

P1-0 探索自由：读取项目任意已有文件、阅读现有代码、上网调研——这些都
不算"修改"，不受限制，不需要为"该不该读"权衡。限制只发生在落笔修改
代码的那一刻，不发生在读和想的过程中。

P1-1 任务内自主权：在当前任务的模块范围内，具体实现方式、代码组织、
合理的小范围改进，AI 自主决定，不需要事事请示。完成后在 CHANGELOG 说明
思路即可。唯一边界：不越过 P0-1 的模块范围，不构成 P0-2/P0-3 定义的
破坏性变更或项目专属决策。

P1-2 任务驱动与排序自主权：开发基于 REQUESTS.md，可按依赖关系自主调整
执行顺序，记录调整原因即可，不需要事先请示。每处改动必须能对应到具体
REQ 编号。

P1-3 增量优先：能用增量方式实现的（新增字段/新增方法/新增可选参数），
直接做，不停下来问。只有确认必须用破坏性修改才能实现时，才触发 P0-2。
禁止静默修复——任何修复都要记录到 CHANGELOG。

P1-4 完成后同步：更新 CHANGELOG.md，REQUESTS.md 标记 completed；涉及
模块/接口变更同步 MODULES.md；涉及业务规则或技术知识的新增/调研，写入
KNOWLEDGE.md 对应条目并标注来源。

## P2｜参考层

P2-1：代码风格尽量跟现有项目一致。
P2-2：不执行项目启动/构建/运行命令，只给执行步骤说明。

## 提交前自查

改动是否越过模块边界；是否存在未经确认的破坏性变更；是否把网络调研当成
了项目专属决策的唯一来源；CHANGELOG 和 REQUESTS 是否更新；涉及模块或
知识变更，MODULES.md / KNOWLEDGE.md 是否同步。任一项没做到，不能提交。
